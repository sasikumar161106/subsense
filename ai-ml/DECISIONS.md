# SubSense Layer 4 Architecture Decision Record (ADR)

## ADR-001: Resolution of Feature Vector Dimension Discrepancy (12th Feature)

### Status
**Accepted / Pre-Resolved**

### Context
In the SubSense Layer 4 Baseline Technical Architecture Specification (`DOC-ID: SUBSENSE-TDD-ML-004`), Section 4.2 outlines a feature store vector schema consisting of 11 variables across three categories:
- **Kinematic Deformation (5 variables)**: `tilt_mean`, `tilt_std`, `tilt_slope_dt`, `disp_max`, `disp_rate_mm_h`
- **Seismic / Vibration Energy (3 variables)**: `vib_rms_max`, `vib_spectral_energy_10_50hz`, `crest_factor`
- **Spatial Topology Context (3 variables)**: `nearest_neighbor_dist_m`, `dist_to_goaf_edge_m`, `pillar_stress_index`

However, Section 5.1 explicitly specifies that the Unsupervised Anomaly Detection engine ingests a **"12-dimensional engineered rolling feature vector"**. 

### Decision & Rationale
To resolve this discrepancy without introducing synthetic or ungrounded proxy signals, the raw `crack_index` telemetry measurement (already present in the raw MQTT sensor payload schema defined in Section 4.1) is incorporated as the **12th feature** of the feature vector, passed through un-transformed alongside the 11 engineered rolling variables. In strata mechanics, differential surface shear strain (`crack_index`) is an essential, high-fidelity physical indicator of tensile rock fracturing that operates on instantaneous fracture dynamics rather than moving-average kinematics. Preserving `crack_index` as an un-transformed 12th channel provides the unsupervised Autoencoder and Isolation Forest direct visibility into sharp micro-fissuring events that rolling descriptive moments might otherwise smooth out.

### Implementation Mandate
1. The vector dimension is declared as a named constant:
   ```python
   FEATURE_VECTOR_DIM = 12
   ```
   No magic number `12` may be hardcoded anywhere in the codebase.
2. The ordered feature layout is formally defined as:
   - Index 0: `tilt_mean`
   - Index 1: `tilt_std`
   - Index 2: `tilt_slope_dt`
   - Index 3: `disp_max`
   - Index 4: `disp_rate_mm_h`
   - Index 5: `vib_rms_max`
   - Index 6: `vib_spectral_energy_10_50hz`
   - Index 7: `crest_factor`
   - Index 8: `nearest_neighbor_dist_m`
   - Index 9: `dist_to_goaf_edge_m`
   - Index 10: `pillar_stress_index`
   - Index 11: `crack_index` (raw, pass-through)

## ADR-002: Empirical Derivation of $\theta_{accel}$ and $\theta_{vel}$ Deformation Trend Thresholds

### Status
**Accepted / Pre-Resolved**

### Context
In Section 5.2 of the SubSense Baseline Technical Architecture Specification (`DOC-ID: SUBSENSE-TDD-ML-004`), deformation progression trend classification defines three operational regimes based on the numerical first ($d\hat{y}/dt$) and second ($d^2\hat{y}/dt^2$) derivatives of the forecast displacement trajectory:
- **Accelerating**: $d^2\hat{y}/dt^2 > \theta_{accel}$
- **Sustained**: $d\hat{y}/dt > \theta_{vel}$
- **Stable**: otherwise

However, the specification does not provide numerical values for $\theta_{accel}$ or $\theta_{vel}$. Hardcoding guessed magic numbers into the scoring logic is strictly prohibited in life-safety systems.

### Decision & Derivation Method
Initial baseline threshold values are empirically derived from the 2,500 synthetic strata subsidence scenarios generated by the geotechnical numerical bootstrap engine (`gnn.synthetic_fea_generator.GeotechnicalSimulationBootstrap`), modeling coupled FLAC3D/UDEC constitutive rock mechanics (elastic flexure, viscoplastic creep, and dynamic roof caving). Specifically, the 90th percentile of velocity and curvature magnitudes across 28,800 hourly observations of stable/non-caving panels was calculated:
1. **$\theta_{vel} = 0.25\text{ mm/hr}$**: Empirically bounds 90% of elastic mining flexure; any velocity exceedance signifies non-transient viscoplastic bed movement.
2. **$\theta_{accel} = 0.05\text{ mm/hr}^2$**: Exceeds the 90th percentile of elastic curvature ($0.053\text{ mm/hr}^2$); any positive second derivative above this value indicates rapid roof delamination and escalating collapse trajectory.

### Implementation Mandate
1. Both thresholds are exposed as named, site-configurable constants in `config/site_config.yaml` (`trend_classification.theta_vel_mm_h = 0.25`, `trend_classification.theta_accel_mm_h2 = 0.050`) so geotechnical engineers can retune them per coalfield geology without modifying code.
2. The forecasting engine reads these values directly from configuration.

## ADR-003: Pure Countdown Architecture for Predictive Time-to-Critical (TTC)

### Status
**Accepted / Pre-Resolved**

### Context
Section 5.3 specifies projecting LSTM quantile trajectories to first-crossing of the critical deformation threshold $D_{crit}$:
$$\text{TTC}_{critical} = \inf\{ t > t_0 : \hat{y}(t) \ge D_{crit} \} \to [\text{TTC}_{min}, \text{TTC}_{median}, \text{TTC}_{max}]$$
The specification also notes an operational tension between Tier-2 (8-hour) and Tier-3 (12-hour) emergency evacuation triggers.

### Decision & Rationale
The TTC module is strictly built as a **pure countdown model**. It projects quantile trajectories ($\hat{y}_{90}, \hat{y}_{50}, \hat{y}_{10}$) to evaluate sub-hour linear interpolation crossings without embedding any alert escalation or evacuation threshold decision logic. Decoupling the countdown calculation from alerting rules ensures that Phase 2 remains a pure predictive engine; threshold conflict resolution is deferred entirely to Phase 3's Multi-Source Evidence Fusion Engine.

### Implementation Mandate
The `TTCCountdown` class outputs exclusively the raw `[TTC_min, TTC_median, TTC_max]` tuple alongside $D_{crit}$, horizon, and crossing boolean flags.

## ADR-004: InSAR Satellite Macro-Fusion Spatial Divergence & Blind-Spot Detection

### Status
**Accepted / Pre-Resolved**

### Context
Section 5.6 mandates fusing Sentinel-1 C-band Synthetic Aperture Radar (SAR) Line-of-Sight (LOS) interferograms with the terrestrial sensor Kriging surface to detect unmonitored subsidence basins ($\Delta_{InSAR} = |Z_{sensor} - Z_{InSAR}|$). Live Copernicus Open Access Hub / ESA API access is not guaranteed in offline or isolated edge deployments.

### Decision & Rationale
The pipeline implements automated parsing and geometric projection of Level-1 Single Look Complex (SLC) interferograms from Line-of-Sight (LOS) into vertical surface displacement:
$$d_{vert} = \frac{d_{LOS}}{\cos(\theta_{inc})}$$
When live orbital SLC scenes are unavailable, the ingestion pipeline generates a calibrated, representative C-band scene (5.405 GHz, $\lambda = 55.46\text{ mm}$) covering the mine concession coordinate frame with synthetic atmospheric phase screening (APS) and coherence decorrelation. The output metadata explicitly marks `is_synthetic_validation = True` for regulatory transparency.

### Implementation Mandate
High divergence is defined as an explicit, configurable threshold ($\theta_{div} = 8.0\text{ mm}$ default), and candidate relocation blind spots are clustered outside the sensor network buffer radius ($R_{buffer} = 120\text{m}$) using connected-component analysis with area and priority grading.

## ADR-005: Multi-Source Evidence Fusion Engine & TTC Critical Tier Trigger Resolution

### Status
**Accepted / Pre-Resolved**

### Context
In the SubSense Layer 4 specification, Section 5.7 mandates an "Immediate Emergency Escalation" auto-trigger at $\text{TTC}_{median} < 8.0\text{h}$, while the Section 6 CRITICAL tier table lists a condition of $\text{TTC}_{median} \le 12.0\text{h}$ alongside Warning conditions and rapid LSTM acceleration. Additionally, the specification lists trigger evidence as an informal checklist rather than explicit boolean logic, introducing ambiguity that could lead to inconsistent tier escalations.

### Decision & Rationale
1. **Explicit Conflict Resolution**: The $8.0\text{h}$ trigger operates as a life-safety override that sits inside a $12.0\text{h}$ Critical floor:
   - $\text{TTC}_{median} \le 12.0\text{h}$ (in conjunction with Warning conditions and rapid LSTM acceleration) is sufficient to trigger `CRITICAL`.
   - $\text{TTC}_{median} < 8.0\text{h}$ on its own, regardless of any other conditions, is unconditionally `CRITICAL` (Immediate Emergency Escalation), because an impending collapse within 8 hours is an imminent life-safety emergency that cannot wait for cross-sensor consensus.
   - An instantaneous displacement spike ($\Delta\text{displacement} > 10.0\text{mm}$) also triggers `CRITICAL` unconditionally as a catastrophic dynamic shear fail-safe.
2. **Deterministic Rules Engine**: The fusion decision engine is implemented as a deterministic, auditable boolean rules engine—never a learned or black-box classifier. No single model may unilaterally escalate an incident to WARNING or CRITICAL (with the sole exceptions of the life-safety overrides: $\text{TTC} < 8\text{h}$ and $\Delta\text{displacement} > 10\text{mm}$).
3. **Formal Tier Logic**:
   - **ADVISORY**:
     $$(S_{node} > 0.65) \land (\text{is\_single\_sensor\_uncorroborated}) \land (\text{LSTM} == \text{STABLE}) \land (\text{confidence} < 0.60)$$
     *Action*: Dashboard notice, node health ping, Level 1 audit log.
   - **WARNING**:
     $$(S_{node} \ge 0.75 \text{ across } \ge 2\text{ channels}) \land (C_{corr} \ge 0.70 \text{ at } \le 120\text{m}) \land (R_{GNN} \ge 0.70) \land (\text{LSTM} == \text{SUSTAINED})$$
     *Action*: SMS/Telegram to geotechnical manager, inspection dispatch, Level 2 DGMS-tracked.
   - **CRITICAL**:
     $$(\text{Warning Conditions} \land \text{TTC}_{median} \le 12.0\text{h} \land \text{LSTM} == \text{ACCELERATING}) \lor (\text{TTC}_{median} < 8.0\text{h}) \lor (\Delta\text{displacement} > 10.0\text{mm})$$
     *Action*: Automated sirens, conveyor cutoff, zone evacuation, Level 3 audit.

### Implementation Mandate
1. The rules engine must achieve 100% branch test coverage, with one unit test per decision table row asserting correct tier firing.
2. Every emitted alert must contain contributing sensors, corroborating neighbor node IDs, and a structured plain-language summary.

## ADR-006: Composite Confidence Scoring Formulation & Live Telemetry Wiring

### Status
**Accepted / Pre-Resolved**

### Context
Section 5 of the SubSense specification outlines a composite confidence scoring formula:
$$\text{Confidence} = w_1 \cdot \text{Agreement}(\text{IsoForest}, \text{LSTM}, \text{GNN}) + w_2 \cdot C_{corr} + w_3 \cdot Q_{mesh}$$
However, the source document leaves the weights $w_1, w_2, w_3$ unspecified.

### Decision & Rationale
1. **Initial Calibration Weights**:
   - $w_1 = 0.50$: Inter-model consensus is weighted highest because model agreement is least correlated with any single point of failure (sensor noise, bad training window, or local edge fault).
   - $w_2 = 0.30$: Physical spatial-temporal cross-correlation ($C_{corr}$) ensures that physical wave propagation across neighbors confirms the event.
   - $w_3 = 0.20$: Telemetry mesh QoS ($Q_{mesh}$) scales confidence based on packet delivery ratio, battery reserve, and RSSI link budget.
   - Constraint: $w_1 + w_2 + w_3 = 1.0$.
2. **Configurability & Calibration**:
   - Weights are externalized in configuration (`config/site_config.yaml`).
   - An automated calibration script (`scripts/calibrate_confidence_weights.py`) re-tunes weights via bounded optimization against historical ground-truth incident datasets.
3. **Live QoS Wiring**:
   - $Q_{mesh}$ is wired directly into Phase 1's live `ingestion.qos_tracker.QoSTracker` metrics (`0.60 * PDR + 0.25 * BattNorm + 0.15 * RSSINorm`), prohibiting ungrounded placeholders.
